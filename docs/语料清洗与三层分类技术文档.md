# 语料清洗与三层分类技术文档（通用方法）

**版本**：v1.1（2026-11-03，通用化修订）
**定位**：与主题无关的方法规范。适用于任何「大规模自述/社群文本 → 归因或主题分类」的语料工程：患者自述、产品差评、员工心声、社区求助帖等。文中出现的具体类别、数字、案例全部来自一个已完成的实例项目（抑郁自述语料），只作示范，不构成方法的一部分；换主题时，类别体系与词典全部重建，方法与参数不变。
**配套实现**（实例项目的代码，可作参考实现）：`depression-corpus-tools` 仓库——清洗 `clean_v22.py`、一级分类 `classify_v22.py`、二级细项 `classify_sub3.py`、三级 `extract_fine.py` / `count_fine.py`、词频挖掘 `mine_vocab.py`、抽检 `spotcheck_sub.py`、词典定版 `sub_dicts.json`。

## 0. 总览：四段流水线

```
原始抓取 (data/*.jsonl)
  → ① 清洗：统一字段、全局去重、分来源落盘 (data_clean/*.jsonl)
  → ② 一级分类：研究问题定义的大类 + 非主题桶（短语词典匹配）
  → ③ 二级细项：每大类拆 5–9 个细项（短语 + 窗口共现），逐类给出比例
  → ④ 三级具体条目：在细项帖池内再挖掘、逐项精数、每项附原文句子作证据
```

设计原则（硬性约定，任何主题都保留）：

1. **口径先于数字**。所有比例的分母是「已分类」文本（至少命中一个主题类的文本）；未述及主题、未分类文本一律排除出分母，另行报告。多标签：一篇文本可同时属于多类，各类比例可合计超过 100。
2. **每层可独立重跑**。清洗、每一级分类都是独立脚本，输入输出均为 JSONL/JSON；改词典只重跑受影响的层。
3. **数字必须过抽检**。任何新计数方法上线前，先随机抽样人眼验精度（见 §5），不过关不发布。
4. **下限要声明**。短语法必然漏检；凡属短语精数的结果，对外表述为「至少」，不冒充精确值。
5. **落盘即验收**。任何抓取/处理进程启动后 2 分钟内检查落盘条数，防止「进程在跑、数据是空/重复」的静默失败。

## 1. 清洗层（通用）

### 1.1 统一记录格式（JSONL，一行一条）

```json
{"source": "...", "id": "...", "title": "...", "text": "...", "chars": 1234, "created_utc": 1690000000, "group": "..."}
```

- 各来源先各自映射到此格式再合并处理。
- 不同性质的文本分开成流（如帖子与评论），因为两者单位性质不同、进入分类的长度阈值也不同（实例：帖 ≥200 字、评论 ≥100 字）。

### 1.2 清洗步骤

1. 流式读取全部来源，避免整库载入内存（语料可达数百万条、十亿级字符）。
2. **全局去重**：以规范化文本哈希为准，跨来源去重。公开数据集之间常有整份复制，不去重会把同一批文本计多遍（实例：三个「不同」的公开数据集实为同一份 7,731 行数据）。
3. 长度与质量粗筛：过短（纯表情、纯链接）剔除；语言不作硬过滤，但分类词典语种覆盖不足时，非主力语种的未分类率会系统性偏高，须在报告中注明。
4. 按来源分别落盘 + 出清洗报告（每来源：原始数 → 保留数 → 总字符数）。

### 1.3 数据陷阱清单（清洗层必须防）

| 陷阱 | 形态 | 对策 |
|---|---|---|
| 同一数据集多处镜像 | 同一份数据被多个发布者重复上传 | 全局哈希去重 |
| 分页接口假象 | 某来源分页每页返回第 1 页内容，「深抓数千条」去重后仅剩百余 unique | 去重后复核 unique 数，异常即整源作废重审 |
| 来源自带标签伪影 | 某数据集的标签分布是其自带字典的产物，不是世界分布 | 跨语料百分比永不直接比较；只在同一口径内比较 |
| 低价值反应文本 | 弹幕、表情回复量大但无归因价值 | 采集层即排除出分析语料 |

## 2. 一级分类（通用框架）

### 2.1 类别体系如何定

- **主题类**：由研究问题定义，数量以 10–15 个为宜，互斥不是要求（多标签），但每个类须有明确的「命中即算」判据。
- **非主题桶**：与主题相邻但不属于研究问题的文本（如只谈处理过程不谈原因）单列成桶，不进主题分母——否则会稀释所有比例。
- **分档口径**（当核心概念有强弱之分时）：同一概念设严/宽/痕迹多档词表并行报告，档与档的差距本身就是结论的一部分（如「明文提及」vs「自述归因」vs「出现相关痕迹」）。

### 2.2 实现

- 词典短语匹配，引擎用 Aho-Corasick，单遍扫描同时匹配全部类别的全部短语；百万级文本全量分类为分钟级。
- 词典为人工维护的多语言短语表，按类别组织，定版后存档为机器可读文件（JSON），与结果一起版本化。
- 环境教训：若运行环境会周期性重启且系统级安装会被清空，依赖库须装入工作区本地目录并在脚本内作路径兜底。

## 3. 二级细项（关键层：方法演化史即复用指南）

本层有三版迭代，成败规律与主题无关，是本方法最值得复用的部分。

### 3.1 v1：纯短语——失败模式

每细项写一组「标准短语」。结果：**陈述型细项可用**（当事人会用固定句式报告的，如分手、考试），**叙事型细项全线报废**（当事人以讲故事方式叙述的，如家庭冲突、被困处境）——后者检出率低到个位数百分比，等于没有。原因：真人是讲故事的，不会用标准句式说出自己的处境。
