# 语料清洗与三层分类技术文档

**版本**：v1.0（2026-11-03）
**适用对象**：患者/社群自述类大规模文本语料（本项目：抑郁主题，Reddit 为主 + 多平台）
**配套代码**：`depression-corpus-tools` 仓库（清洗 `clean_v22.py`、分类 `classify_v22.py`、细项 `classify_sub*.py`、三级 `extract_fine.py` / `count_fine.py`、词频挖掘 `mine_vocab.py`、抽检 `spotcheck_sub.py`）
**词典定版文件**：`sub_dicts.json`（含窗口参数与完整二级词典，机器可读）

---

## 0. 总览：四段流水线

```
原始抓取 (data/*.jsonl)
  → ① 清洗：统一字段、全局去重、分来源落盘 (data_clean/*.jsonl)
  → ② 一级分类：13 个原因大类 + 非因类桶（短语词典匹配）
  → ③ 二级细项：每类拆 5–9 个细项（短语 + 窗口共现），逐类给出比例
  → ④ 三级具体原因：在细项帖池内再挖掘、逐项精数、每项附真人原句
```

设计原则（本项目的硬性约定，换语料也应保留）：

1. **口径先于数字**。所有比例的分母是「已分类」帖（至少命中一个原因类的帖）；无原因、未分类帖一律排除出分母，另行报告。多标签：一帖可同时属于多类，各类比例可合计超过 100。
2. **每层可独立重跑**。清洗、每一级分类都是独立脚本，输入输出均为 JSONL/JSON 文件；改词典只重跑受影响的层。
3. **数字必须过抽检**。任何新计数方法上线前，先随机抽样人眼验精度（见 §5），不过关不发布。
4. **下限要声明**。短语法必然漏检；凡属短语精数的结果，对外表述为「至少」，不冒充精确值。
5. **落盘即验收**。任何抓取/处理进程启动后 2 分钟内检查落盘条数，防止「进程在跑、数据是空/重复」的静默失败。

## 1. 清洗层

### 1.1 统一记录格式（JSONL，一行一条）

```json
{"source": "reddit", "id": "...", "title": "...", "text": "...", "chars": 1234, "created_utc": 1690000000, "subreddit": "..."}
```

- 各来源（Reddit 帖/评论、Bilibili、5ch、Patient.info、HuggingFace 数据集等）先各自映射到此格式再合并处理。
- 评论与帖子分开成流（`reddit_clean.jsonl` 与 `reddit_comments_clean.jsonl`），因为两者的单位性质不同，分类口径也不同（帖 ≥200 字、评论 ≥100 字进入长文本分类）。

### 1.2 清洗步骤（`clean_v22.py`）

1. 流式读取全部来源，避免整库载入内存（语料规模：原始数百万条、十亿级字符）。
2. **全局去重**：以规范化文本哈希为准，跨来源去重。必须做：公开数据集之间存在整份复制（本项目实测：HuggingFace 上 mrjunos / hugginglearners / ShreyaR 三个「不同」数据集实为同一份 7,731 行数据，不去重会把同一批帖计三遍）。
3. 长度与语言粗筛：过短（纯表情、链接帖）剔除；语言不作硬过滤（多语言语料），但分类词典以英文为主时，非英文帖的未分类率会系统性偏高，需在报告中注明。
4. 按来源分别落盘 + 出清洗报告（`cleaning_report_v22.json`：每来源 原始数 → 保留数 → 总字符数）。

### 1.3 已知数据陷阱（清洗层必须防）

| 陷阱 | 本项目实测 | 对策 |
|---|---|---|
| 同一数据集多处镜像 | HF 三个数据集实为同一份 | 全局哈希去重 |
| 分页接口假象 | 某论坛游客分页每页返回第 1 页内容，「深抓 4,108 帖」去重后仅 189 条unique | 去重后复核 unique 数，异常即整源作废重审 |
| 平台字典伪影 | 中文 OESD 数据集「孤独 76.6%」是其自带标签字典的产物 | 跨语料百分比永不直接比较；只在同一口径内比较 |
| 弹幕/反应文本 | 弹幕量大但无归因价值 | 采集层即排除出分析语料 |

## 2. 一级分类（13 大类）

### 2.1 类别体系

原因类（13）：家庭/父母、工作/学业、亲密关系、孤独/孤立、疾病/疼痛、童年创伤、丧亲/丧失、经济窘迫（严）、困住/逃不掉、遗传/家族史、睡眠、产后、无缘无故（自述无原因，本身即一个实质类别）。

非因类（单列，不进原因分母）：治疗/药物、想死未述因、症状描述、邻近诊断。

经济类设三档口径并行报告：**严**（明文经济困境词）、**宽**（含「困住型」经济表述）、**痕迹**（出现任何金钱相关词）。三档差距本身就是结论的一部分（自述归因 vs 结构痕迹）。

### 2.2 实现

- 词典短语匹配，引擎为 Aho-Corasick（`pyahocorasick`），单遍扫描同时匹配全部类别的全部短语；280 万级帖子全量分类约 3 分钟。
- 词典为人工维护的多语言短语表（英/中/日为主），以类别为键存于脚本（`classify_all.py` 的 `EN` 表为一级定版）。
- 并发教训：运行环境会周期性重启且系统级 pip 安装会被清空——依赖库须装入工作区本地目录（如 `pylibs/`）并在脚本内 `sys.path` 兜底，否则重启后分类脚本会因缺模块崩溃。

### 2.3 口径示例（本项目中期快照，Reddit 长帖）

已分类帖占长帖 70.8%；分类内：家庭 52.9、工作 43.2、关系 33.2、孤独 17.0、疾病 12.6、创伤 11.1、丧亲 9.4、经济严 11.1 / 宽 14.8 / 痕迹 59.5、遗传 0.7（每一百篇已分类帖）。

## 3. 二级细项（三层细化的关键层，方法演化史即复用指南）

本层经历三版迭代。三版的成败就是这套方法最值得复用的部分。

### 3.1 v1：纯短语——失败模式

每细项写一组「标准短语」（如丧母 = "lost my mom"）。结果：陈述型细项可用（分手 19.1、学业压力 19.1），但**叙事型细项全线报废**：家庭组全部细项 ≤1.5（家暴、控制、忽视都检不出来），困住组全部 <1。原因：真人是讲故事的，不会用标准句式说出自己的创伤。

### 3.2 词频挖掘：让语料自己教用词（`mine_vocab.py`）

对每个一级类别，抽取其帖子（一类上限 6 万篇）统计内容词与双词组频次，先看真实用词再改词典。本项目挖出的关键事实：

- 「student loans」在经济类自成一个大项（约 5,000 次）→ 从「债务」中拆出独立细项「学生贷款」；
- 家庭类高频出现兄弟姐妹词 → 新增「兄弟姐妹问题」细项；
- 「taking care」高频 → 「照顾患病家人」需要共现规则才能检出；
- 「isolated myself」→ 孤独类拆出「自我隔离/退缩」；
- 经济类：「pay rent / pay bills / credit card / student loans / minimum wage / cannot afford」都是真实高频讲法，全部入词典。

**规则：新细项与新词条只能来自语料证据，不许坐在桌前猜。**

### 3.3 v2：全文共现——召回修好，精度报废

叙事型细项改用共现规则：A 组词（如亲属词 mom/dad/parents）与 B 组词（如行为词 hit/yelled/drunk）在**同一帖任意位置**出现即命中。召回暴涨（家暴 1.5 → 25.5，目睹家暴 0 → 21.4），但抽检（§5）发现精度崩坏：长帖里什么词都有，丧子被计到 47.4（「孩子」与死亡词在长帖中随便相撞），丧母 43.5 同样虚高。

### 3.4 v3：窗口共现——定版方法（`classify_sub3.py` + `sub_dicts.json`）

共现改为**近距离共现**：A、B 两组词必须在 **150 字窗口内**同时出现才算命中（同一件事通常在一两句内讲完）。实现：Aho-Corasick 迭代时记录 A/B 标签的命中位置，双指针求最小间距 ≤150。

同时两个配套修正：

- **亲属归属类改纯短语**：丧子/流产只认明文句式（"lost my baby"、"my son died"、miscarriage、stillborn…），47.4 → 0.9（宁作下限，不作假数）。
- **死亡词表收紧**：删除裸词 "dead"（习语 dead inside / dead tired）、裸 "suicide"（发帖者自身的自杀意念会污染丧亲归属）。

v3 抽检复核：命中池普遍收缩 40–60%，精度明显改善。可信度分级（必须随数字一起发布）：

- **短语类细项**：抽检无明显问题，可信，可当实数用；
- **共现类细项**：仍系统性偏高（长帖词密度使然），定位为**上限估计**，实际值约其六至七成；排序可参考，绝对值不作实数引用。

## 4. 三级：具体原因层（`extract_fine.py` / `count_fine.py`）

### 4.1 工序

1. **建池**：用二级定版规则（短语 + 窗口共现）重建该细项的命中帖池，落盘为独立 JSONL。
2. **池内再挖掘**：在池内重跑词频/双词组统计，看这一支人具体在讲什么（注意：停用词表必须完整，漏掉 the/and 等基础功能词会让挖掘结果全是噪声——本项目踩过此坑）。
3. **逐项定短语清单**：人工根据挖掘结果把具体原因定为明文短语组。**本层只用短语，不用共现**——越细越要精度，宁漏勿假。
4. **精数 + 原句抽取**（`count_fine.py`）：逐项计比例（分母 = 池帖数），并按句切分抽取含命中短语的原句（50–220 字）作证据，每项 3 句。
5. **异常即拆**：任何单项比例高得不合理，必须逐短语拆开验贡献度，再按上下文拆分或修正（见 4.2 案例）。

### 4.2 本层的三个实测案例（方法自带纠错的证据）

- **homeless 拆分**：房租池中「无家可归」初计 71.9%，逐词验发现单个词 "homeless" 占 71.4%——池内七成人用过这个字，但语境分两类。按上下文短语拆分后：**已经无家可归 22.2**（瞓车/沙发冲浪/收容所）+ **濒临/恐惧无家可归 23.3**——两个都是真实且不同的具体原因。
- **子串陷阱**：「靠福利救济」初计 61.7%，原因是短语表中的 "ssi" 是 "depre**ssi**on" 的子串，全池假命中。修正为 "on ssi / on disability / unemployment benefits" 等完整短语后：**1.9**。规则：**任何短于 4 字符的词条禁止裸子串匹配**；缩写类词条必须带上下文词。
- **归属窗口**：丧母池内计「癌症病逝」，裸短语 "died of cancer" 会命中「爸爸癌症去世」的帖（原句抽查暴露）。改用**归属窗口**：死因短语须出现在亲属词（mom/mother/mum）120 字以内。癌症 2.7 → 2.1、突然离世 5.7 → 3.5。规则：**「谁 + 什么原因」型细项必须做归属约束**。
